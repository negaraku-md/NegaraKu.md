เกือบทุกอย่างที่เขียนเกี่ยวกับการตัดสินใจนี้เขียนโดยคนที่ขายคำตอบหนึ่ง ดังนั้นจงเริ่มจากกลไกสองอย่างเดียวที่ LHDN
ยอมรับจริงใน Table 2.1 ของ e-Invoice Guideline: **MyInvois Portal** และ **API** ผู้ให้บริการ Peppol ผู้ให้บริการ
เทคโนโลยีที่ไม่ใช่ Peppol และ middleware ไม่ใช่ตัวเลือกที่สาม — พวกมันเป็นสามวิธีในการเข้าถึง API

## กลไกสองอย่าง

| | MyInvois Portal | API |
| --- | --- | --- |
| ต้นทุน | ฟรี ผ่านการเข้าสู่ระบบ **MyTax** | สร้างหรือซื้อสิทธิ |
| อินพุต | แบบทีละรายการ หรือ **การอัปโหลดแบทช์ของสเปรดชีต Excel ที่กำหนดไว้ล่วงหน้า** | XML หรือ JSON ตาม **UBL 2.1** |
| ลายเซ็น | จัดการโดย Portal | **ใบรับรองดิจิทัล** ของคุณ (.cer หรือ .pfx) |
| ความเหมาะสมที่ LHDN ระบุ | เข้าถึงได้ทุกผู้เสียภาษี; ธุรกิจที่การเชื่อมต่อ API ไม่มี | ปริมาณสูง; ต้องลงทุนและเปลี่ยนระบบล่วงหน้า |
| เส้นทาง | หนึ่ง | ERP โดยตรง ผู้ให้บริการ **Peppol** ผู้ให้บริการ **ที่ไม่ใช่ Peppol** |

ทั้งสองผลิตสิ่งเดียวกัน: IRBM Unique Identifier Number ประทับเวลาการตรวจสอบ และ QR code บน visual representation

## ประเมินขนาดปัญหาก่อนช้อป

คำถามไม่ใช่รายได้ของคุณ มันคือ **คุณต้องส่งเอกสารกี่ฉบับในหนึ่งเดือน** และจำนวนมักใหญ่กว่าที่คนคาด:

1. e-Invoice แบบธุรกรรมให้ผู้ซื้อที่ขอ
2. e-Invoice แบบรวม — หนึ่งหรือมากกว่าต่อเดือน ต่อสาขาหากคุณแยก
3. **e-Invoice แบบออกเอง** — ค่าคอมมิชชัน ผู้ขายต่างประเทศ ผู้ให้เช่าบุคคลธรรมดา ดอกเบี้ยส่วนใหญ่ เงินปันผล การชำระคืนทุน
4. ใบลดหนี้ ใบเพิ่มหนี้ และใบคืนเงิน

จากนั้นใช้ข้อยกเว้นสองข้อที่ทำลายการประมาณแบบไร้เดียงสา **ธุรกรรมเดียวใด ๆ เกิน RM10,000** ต้องเป็นแบบธุรกรรม
ในทุกอุตสาหกรรม ตั้งแต่วันที่ 1 มกราคม 2026 และเก้ากิจกรรมใน Table 3.6 ของ e-Invoice Specific Guideline รวมไม่ได้
เลย — ยานยนต์ ตั๋วเครื่องบิน สัญญาก่อสร้าง การจ่ายเงินตัวแทนและผู้แทนจำหน่าย การจ่ายเงินพนัน ไฟฟ้า โทรคมนาคม

ร้านซ่อมที่ขายรถสามคันต่อเดือนมีภาระงาน Portal ที่ไม่สำคัญ ผู้ค้าปลีกโทรคมนาคมที่มีสมาชิกรายเดือน 4,000 รายไม่มี
และการรวมไม่ว่ามากเท่าใดก็ไม่ช่วยมัน

**ปริมาณการออกใบแจ้งหนี้ด้วยตนเองคือความประหลาดใจตามปกติ** บริษัทที่มีใบแจ้งหนี้ขาย 40 ใบต่อเดือนและการจ่าย
ค่าคอมมิชชันตัวแทน 600 รายเป็นธุรกิจ e-Invoicing ปริมาณสูง ไม่ว่าสมุดบัญชีการขายจะบอกอะไร

## ที่ซึ่ง Portal หยุดทำงานอย่างแท้จริง

- **ต้นทุนการป้อนข้อมูล** เอกสารแบบธุรกรรมทุกฉบับต้องมีชื่อผู้ซื้อ TIN หมายเลขจดทะเบียน ที่อยู่ หมายเลขติดต่อ และ
  หมายเลข SST ที่คีย์หรือโหลดจากสเปรดชีต
- **นาฬิกา 72 ชั่วโมง** หน้าต่างการยกเลิกและการปฏิเสธนับจากการตรวจสอบ กระบวนการมือที่ส่งรายสัปดาห์ใช้มันไม่ได้
- **การกระจุกตัวสิ้นเดือน** e-Invoice แบบรวมครบกำหนดภายใน **เจ็ดวันตามปฏิทิน** หลังสิ้นเดือน เพิ่มเข้าทุกอย่างอื่น
- **การกระทบยอด** Portal ให้คุณ XML, JSON, เมทาดาทา ตาราง และการดึง PDF — แต่การจับคู่เอกสารที่ตรวจสอบแล้ว
  กลับเข้าสมุดบัญชีของคุณเป็นแบบมือ

## ที่ซึ่ง API มีต้นทุนมากกว่าใบอนุญาต

- ต้องได้ **ใบรับรองดิจิทัล** ติดตั้งและหมุนเวียน
- **ขีดจำกัดการส่งเข้มงวด:** 100 เอกสารและ 5MB ต่อการส่ง, 300KB ต่อเอกสาร การแบทช์และการย่อขนาดเมื่อจำเป็น
  เป็นปัญหาของคุณ
- **การตรวจสอบสองขั้น** *Submitted* ไม่ใช่ *Valid* โครงสร้าง ช่องหลัก และรหัสถูกตรวจทันที; ลายเซ็น ผู้เสียภาษี เอกสาร
  ที่อ้างอิง และเอกสารซ้ำถูกตรวจในเบื้องหลัง การเชื่อมต่อใดที่ถือว่าการตอบรับแบบ 202 เป็นความสำเร็จจะสะสมเอกสาร
  ที่ไม่ถูกต้องอย่างเงียบ ๆ
- **การจัดการโทเคน** โทเคนเข้าสู่ระบบใช้ได้ 60 นาทีและมีไว้ให้ใช้ซ้ำ ไม่ใช่สร้างต่อคำขอ การจำกัดอัตราคืน 429 พร้อม
  ส่วนหัว `Retry-After`
- **ข้อมูลหลัก** TIN ผู้ขายและผู้ซื้อ BRN 12 หลักใหม่ รหัส MSIC และหมายเลข SST ต้องถูกต้องก่อนสิ่งนี้ทำงาน

## การเลือกเส้นทางสู่ API

| เส้นทาง | เหมาะกับ | ต้องระวัง |
| --- | --- | --- |
| **การเชื่อมต่อ ERP โดยตรง** | ERP ที่จัดตั้งแล้วพร้อมการปรับให้เข้ากับมาเลเซียที่ดูแลอยู่ หรือความสามารถวิศวกรรมภายใน | การบำรุงรักษาต่อเนื่องเมื่อเวอร์ชันแนวทางเปลี่ยน — v4.7 และ v4.8 ทั้งคู่มาถึงวันที่ 7 กรกฎาคม 2026 |
| **ผู้ให้บริการ Peppol** | ธุรกิจที่ต้องการการแลกเปลี่ยนเอกสารที่ทำงานร่วมกันได้กับคู่ค้าด้วย | Peppol ไม่ใช่ข้อกำหนดของ MyInvois; อย่าจ่ายสำหรับมันราวกับว่าเป็น |
| **ผู้ให้บริการเทคโนโลยีที่ไม่ใช่ Peppol / middleware** | ระบบต้นทางหลายระบบ กลุ่ม POS หรือ ERP ที่ไม่มีการปรับให้เข้ากับมาเลเซีย | การเก็บข้อมูล เงื่อนไขการออก และว่าพวกเขาส่งภายใต้ข้อมูลรับรองของตนเองหรือไม่ |

LHDN ไม่รับรอง ให้การรับรอง หรืออนุมัติผู้ให้บริการใด หากผู้ขายอ้างสถานะได้รับอนุมัติจาก LHDN ขอดูมัน

## คำถามเรื่องตัวกลางที่ไม่มีใครถาม

SDK ระบุว่าตัวกลางส่งโดยใช้ **Client ID และ Client Secret ของตนเอง** และเข้าถึงได้เฉพาะ e-Invoice **ที่ตน**ส่ง —
พวกเขาดึงเอกสารที่ผู้เสียภาษีส่งเองอย่างอิสระไม่ได้

ผลสองประการที่ควรค่าแก่การเขียนในสัญญา:

- **การเปลี่ยนผู้ให้บริการไม่ยกประวัติการส่งของคุณข้าม** วางแผนสำหรับช่วงรันขนานและสำหรับที่จัดเก็บของคุณเอง
- **ความรับผิดไม่โอน** Section 82C ของ Income Tax Act 1967 วางหน้าที่ที่ผู้เสียภาษี; s.120(1)(d) ทำให้การฝ่าฝืนเป็น
  ความผิด การหยุดชะงักของผู้ขายคือการไม่ปฏิบัติตามของคุณ

เรื่องการหยุดชะงัก LHDN ให้การผ่อนปรนหนึ่งอย่าง Section 2.5.4 ของ e-Invoice Guideline ระบุว่าเมื่อระบบ MyInvois
เองหยุดเพราะการบำรุงรักษาหรือเหตุผลทางเทคนิคและผู้เสียภาษีสามารถแสดงหลักฐานความพยายามในการปฏิบัติตาม
อธิบดีจะประเมินกรณีเป็นรายกรณีและอาจไม่ดำเนินการ นั่นครอบคลุมการหยุดของ LHDN ไม่ใช่ของผู้ขายคุณ

## เส้นทางการตัดสินใจ

1. **คุณได้รับยกเว้นหรือไม่?** ต่ำกว่ามูลค่าการซื้อขายรายปี RM1,000,000 หยุด
2. **นับเอกสารรายเดือน** ข้ามสี่หมวดข้างต้น
3. **ต่ำกว่าประมาณหนึ่งร้อย ส่วนใหญ่แบบรวม?** Portal พร้อมการอัปโหลดแบทช์ Excel ทบทวนรายปี
4. **หลักร้อยถึงหลักพัน ระบบต้นทางเดียว?** ถามผู้ขาย ERP ของคุณว่าการปรับให้เข้ากับ MyInvois ครอบคลุมอะไร —
   โดยเฉพาะประเภทออกเอง 11 ถึง 14 และช่องภาคผนวกสำหรับการนำเข้า
5. **หลักพัน หรือระบบต้นทางหลายระบบ หรือกลุ่ม POS?** Middleware เลือกบนการเก็บข้อมูลและเงื่อนไขการออกมากกว่า
   รายการฟีเจอร์
6. **ไม่ว่าคุณเลือกอะไร พิสูจน์มันตั้งแต่ต้นจนจบก่อนช่วงผ่อนปรนของคุณสิ้นสุด** — 31 ธันวาคม 2027 สำหรับ phase 4
   และผ่านไปแล้วสำหรับ phase 1 ถึง 3

## ข้อผิดพลาดที่พบบ่อย

- **ซื้อก่อนนับ** จำนวนเอกสาร รวมแบบออกเอง เป็นอินพุตทั้งหมดของการตัดสินใจนี้
- **สันนิษฐานว่า Peppol เป็นข้อบังคับ** มันเป็นหนึ่งในสามเส้นทาง API
- **เชื่อการอ้างการรับรอง** LHDN ไม่เผยแพร่รายการผู้ขายที่ได้รับอนุมัติ
- **ถือว่าการตรวจสอบเป็นแบบซิงโครนัส** สี่ในเจ็ดตัวตรวจสอบทำงานในเบื้องหลัง
- **ข้ามการทำความสะอาดข้อมูลหลัก** หมายเลขจดทะเบียน SSM เก่าและ TIN ที่ล้าสมัยจะไม่ผ่านตัวตรวจสอบผู้เสียภาษี
  ไม่ว่าการเชื่อมต่อจะดีเพียงใด
- **ทดสอบด้วยข้อมูลสะอาด** ทดสอบด้วยผู้ขายต่างประเทศ บุคคลธรรมดาที่ไม่มี TIN ใบลดหนี้ และปริมาณสิ้นเดือน เพราะ
  นั่นคือสิ่งที่ทำให้พัง

## หัวข้อที่เกี่ยวข้อง

ดึงบัญชีเจ้าหนี้และลูกหนี้ของเดือนที่แล้ว จำแนกทุกบรรทัดเป็นแบบธุรกรรม แบบรวม หรือแบบออกเอง และนับ ตัวเลขนั้น
ตัดสินกลไก จากนั้นตรวจสอบรายการช่องกับข้อมูลหลักของคุณ เพราะการทำความสะอาดมักใช้เวลานานกว่าการเชื่อมต่อ
