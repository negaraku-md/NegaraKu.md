NegaraKu.md · Language expansion

Adding தமிழ் Tamil
as the fourth language

A phased plan to ship Tamil (ta, served at /ta) alongside Malay, English and Chinese — completing Malaysia's three founding language communities. Every touchpoint below is grounded in the current codebase map, and the same shape becomes the template for Japanese and Korean.

~1.5–2 wks infrastructure weeks content — the long pole 1,073 masters to translate ~110 UI keys · ~140 subcategories

Track A — Infrastructure

Bounded, one-time engineering: the Locale type, routes, fonts, i18n plumbing, pipelines, and a Facebook Page. Ship it once; it carries every future language.

Track B — Translation content

The bulk work: ~1,073 article masters plus the large typed taxonomy and UI-copy surfaces. Gated by human review throughput — runs for weeks, in parallel with the FB backlog drip.

The completeness lever

One edit surfaces the entire type-level worklist

The master type lives at src/lib/categories.ts:16 — type Locale = 'ms'|'en'|'zh'. Adding | 'ta' and running astro check makes TypeScript flag every Record<Locale, …> literal missing a ta key. That compiler error list is the exhaustive checklist for the i18n, SEO, and taxonomy surfaces — so nothing localizable is silently left in English.

The quiet risk is the opposite: the inline L(ms, en, zh) helper in ~44 components falls through to Malay for any non-en/zh locale. Tamil would render readable-but-wrong (Malay text) with no compile error — so those call sites need a deliberate sweep, not a type check.

Phased delivery

0

Decisions & assets

Infra · prep ~0.5 day

Settle the choices the rest of the build hard-codes, and stage the external assets that have lead time.

  • Confirm locale ta at /ta, hreflang tag (ta vs ta-MY), sitemap locale.
  • Pick the Tamil typeface — Noto Sans Tamil (body) + optionally Noto Serif Tamil (headings); vendor via Fontsource like the Latin faces.
  • Create the Tamil Facebook Page and assign it to the existing system user, yielding FB_PAGE_ID_TA (a blank id is safely skipped, so this can trail).
  • Author docs/plans/GLOSSARY-TA.md so the translation pipeline keeps terms of art consistent.
  • Decide feed parity: /ta/rss.xml only (matches en/zh) — no Atom feed.xml.
1

Type & route scaffolding

Infra ~1–2 days

Make ta a first-class locale and stand up its routes. The site renders Tamil URLs immediately — chrome falls back to Malay until Phase 3.

  • categories.ts:16 add | 'ta' → run astro check to enumerate the rest.
  • Runtime lists: LOCALES, LOCALE_NAMES (ta: 'தமிழ்'), localeFromPath() in i18n.ts.
  • Schema: content.config.ts lang + masterLanguage zod enums.
  • astro.config.mjs — i18n locales + defaultLocale, lastmodFor(), sitemap i18n.locales.
  • Duplicate src/pages/en/** → src/pages/ta/** (33 route files), swapping 'en'→'ta' in each getStaticPaths caller.
  • BaseLayout.astro — add a ta arm to htmlLang and the hreflang map (factor out the repeated expression).
Gateastro build green; /ta/* pages emit <html lang="ta"> and resolve.
2

Fonts — the readability blocker

Infra · critical ~0.5 day

Nothing Tamil is legible until this lands. Neither Montserrat, Lato, nor the CJK fallback covers the Tamil block (U+0B80–U+0BFF), so untreated Tamil renders as tofu — on the page and on OG cards.

  • Self-host @fontsource/noto-sans-tamil; import faces in BaseLayout.astro; add to --font-reading/--font-title in tokens.css; register the family with the fontaine fallback-metrics plugin.
  • OG rasterizer (separate problem): build-og.mjs renders SVG via sharp/librsvg using system-resolved fonts — make a Tamil face available at build time and add it to TITLE_FONT/BODY_FONT stacks.
GateA Tamil sample title renders correctly on-page and on a generated OG card — zero tofu.
3

UI strings

Infra · largest code surface ~2–3 days

Translate the site chrome. Two surfaces: the central string table (type-enforced) and the scattered inline helper (silent Malay fallback — no compiler safety net).

  • i18n.ts STRINGS — add a ta: value to ~110 keys.
  • Widen L(ms, en, zh) → L(ms, en, zh, ta) across ~44 components and update every call site (hundreds of inline page-copy strings). Mechanical — a candidate for a batched multi-agent sweep.
Gateastro check clean; /ta navigation, buttons, and labels read in Tamil.
4

Taxonomy & structured data

Content-in-code ~2–4 days

The localized data baked into Record<Locale> literals — surfaced by the Phase 1 compiler pass. Translation work that lives in source, not article files.

  • subcategories.ts — ~140 subcategory labels (the single biggest taxonomy surface).
  • categories.ts — ~30 category names + blurbs; intros.ts — ~30 curatorial essays.
  • Structured data: seo.ts descriptions + inLanguage, llms.ts intros, sponsors.ts, provenance.ts.
  • Mirrors: OG taxonomy (PILLAR/CAT/SENS), dashboard vitals labels, inline strings in 404.astro / MaintenanceView.
GateAll Record<Locale> sites satisfied; breadcrumbs, chips, and dashboard render Tamil.
5

Pipelines & ops

Infra ~1 day

Teach the generation and distribution scripts about ta so translation, analytics, and Facebook all include it.

  • translate.mjs — LOCALES + LANG_NAME + GLOSSARY-TA; translation-sync.mjs:83 filename regex; validate-frontmatter / flag-needs-update regexes; build-dashboard SITE_LANGS.
  • Facebook: facebook.mjs LANGS + PAGES (FB_PAGE_ID_TA), the hashtag script check (so Tamil tags don't leak onto ms/en posts), and the catNameMap regex (currently ms/en/zh only).
  • Redirect parity: add /ta/… variants across the ~19 retired-slug groups in astro.config.mjs.
GateDry-run translate one article; FB dry-run renders a Tamil sample post correctly.
6

Corpus translation — pilot, then scale

Content · the long pole weeks

The bulk of the effort, deliberately de-risked. Prove the whole chain on a handful of articles before committing 1,000+.

  • Pilot (~10 ranked articles): generate .ta.md, human-review quality, translate:stamp, build, publish, verify on-site + OG + FB.
  • Full corpus: ~1,073 masters through translate.mjs, batched (as the Malay-title sweep was), reviewed by ashton-tan, published via the publish-reviewed flow.
  • FB backlog: Tamil joins the daily drip automatically once FB_PAGE_ID_TA is live and LANGS includes ta.
GatePilot signs off before the full run; translation freshness stays in-sync via the derived stamp.

Launch-gating decision to make

LOCALES drives both the route iteration and the public language switcher. Add ta and Tamil is advertised immediately — while the corpus is still filling in, /ta shows a growing subset. Choose between a soft launch (build the routes but hold Tamil out of the switcher until content crosses a parity threshold) and an open launch (advertise from day one, articles appearing as they're translated). Recommend soft launch through the pilot.
