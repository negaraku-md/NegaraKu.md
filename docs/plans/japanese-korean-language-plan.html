Adding 日本語 Japanese
and 한국어 Korean

The fifth and sixth languages — reaching Malaysia's largest inbound investors and affluent visitors. Both reuse the infrastructure built for Tamil, so this is mostly a content effort with a short CJK-specific engineering delta. Sequenced Japanese first, then Korean.

日本語 ja · at /ja 한국어 ko · at /ko ~2–3 days infra delta / language 1,073 masters × 2

Track A is already built — this plan is the reuse

The Tamil work (the fourth-language plan) established the whole locale machinery: the Locale / ContentLocale split, the loc() Malay-fallback accessor, the 33-file route template, and the pipeline hooks (translate.mjs, facebook.mjs, sitemap/hreflang). Adding a language is now a known, repeatable procedure: clone the route directory, add the locale to a handful of lists, wire one script font, stand up one Facebook Page, then translate. Japanese and Korean each cost a fraction of Tamil's first-time engineering.

The one genuinely new engineering bit

Tamil needed a brand-new script font and a fresh Facebook Page. Japanese and Korean need the same two things (their own Noto CJK faces + one FB Page & token each) — but unlike Tamil, the site already loads a CJK face for Chinese, so the font wiring pattern and the OG rasterizer's CJK width/wrap handling are proven. Net: the font step is lower-risk than it was for Tamil, and there is no right-to-left work anywhere in this roadmap.

Per-language delivery (repeat for ja, then ko)

1

Locale wiring

Reuse~0.5 day

Add the locale to the lists Tamil already parameterised — no new architecture.

  • Extend Locale in categories.ts (… | 'ja'); the loc() fallback already handles it.
  • Add to content.config.ts lang enum, astro.config i18n + sitemap locales, lastmodFor(), BaseLayout htmlLang/hreflang, LOCALE_NAMES (日本語 / 한국어), localeFromPath().
  • Pipelines: translate.mjs LOCALES/LANG_NAME, translation-sync regex, build-dashboard SITE_LANGS.
2

Routes

Reuse~0.5 day

Clone the proven route template — the loc() and t() fallbacks mean chrome renders in Malay until translated.

  • Duplicate src/pages/en/** → src/pages/ja/** (33 files), swap 'en'→'ja' in each getStaticPaths caller, use loc() in the [category] title/description props.
3

CJK font

New per language~0.5 day

The one script-specific step — but de-risked by the existing Chinese CJK wiring.

  • Self-host @fontsource/noto-sans-jp (or -kr); add to tokens.css stacks + fontaine fallback; add a locale === 'ja' web-font block in BaseLayout.
  • Make the face available to the OG rasterizer (build-og.mjs) and add it to the TITLE_FONT/BODY_FONT stacks; the CJK wrap heuristic already exists.
4

Facebook Page

New per language~0.5 day

One new Page per language so the FB backlog drip includes it.

  • Create the Japanese (then Korean) Page, assign to the system user, set FB_PAGE_ID_JA in facebook.mjs PAGES + LANGS; widen the hashtag script-check and catNameMap regex for the new locale.
5

Taxonomy & UI strings

Content-in-code~2–3 days

Add the locale's values to the same surfaces Tamil filled — the structure is settled, only the translations are new.

  • ~110 i18n UI keys, ~44 inline L() call sites, ~140 subcategories, ~30 category names/blurbs/intros, OG/SEO/llms mirrors.
6

Corpus translation

The long poleweeks

Pilot ~10 articles, verify on-site + OG + FB, then translate all ~1,073 masters via translate.mjs, human-reviewed, published through the publish-reviewed flow.

  • Soft launch: hold the locale out of LOCALES (switcher) until the corpus crosses a parity threshold — same gate as Tamil.
